# Audit 2026-11-23: every rule cited

All 101 rules in `coach audit` now have an evidence record (275 retrieved sources in total; every PubMed ID was checked against PubMed). Researched in 6 parallel batches (readiness, pain/ladders, running load, strength/testing, deload/skill, nutrition) plus session-structure/weather by the coach, on top of the 32 records from the 2026-11-22 audit.

**Verdicts:** keep_flagged 51, keep 37, change 11, retire 2

**Evidence levels:** practitioner 37, consensus 15, rct 13, cohort 12, meta_analysis 11, none 8, theory 5

## Proposed changes waiting for the athlete (none applied)

- **season.deload.competition_run_factor** (change, practitioner): No value change. Code PR: make engine/running.py ramp_targets read season.deload.competition_run_factor instead of the hardcoded 0.8 (pass it through RampRules from plan_block.build_outline), and bump the rule version in engine/audit.py. This is wrong if, after wiring, the simulations change output while the config is still at 0.8.
- **season.deload.taper_run_factor** (retire, meta_analysis): Retire season.deload.taper_run_factor (and the hardcoded 0.75 taper branch in engine/running.py ramp_targets), or wire it explicitly as unused. The taper dose lives in the block's taper_volumes [0.8, 0.6, 0.4], which is consistent with Bosquet 2007 / Wang 2023 / Smyth 2021. Config proposal plus a code PR (season model default and running.py), with the rule version bumped in engine/audit.py. This is wrong if any outline path is found that produces a 'taper' week outside an event block (check the simulations).
- **progressions.rules.pain_rule** (change, rct): Clearer/stricter wording, numbers unchanged: 'Session pain > 2/10: regress ROM or switch to an isometric next time and drop one rung. If next-morning pain or stiffness has not returned to its pre-session level, or the movement's session pain is higher than the week before: -15% load, 3 s eccentric, 2 weeks.' Adds the pain-monitoring model's 24 h return-to-baseline and week-to-week trend criteria. Wrong if it triggers regressions on >1 in 4 gated sessions with no later pain/flag signal (over-sensitive, then revisit with the athlete via proposal).
- **code.red_accessory_halving_72h** (change, none): Code PR (bump to v2): halve accessory sets on days 2-3 after a Red only when that Red was joint-driven (same condition as the v2 Red carry) or today's readiness is Yellow/Red; on a Green day after a non-joint Red, train as planned. Wrong if, over the next block, sessions within 3 days of a non-joint Red show higher session RPE at the same loads or a second Red follows within 72 h more often than before.
- **benchmarks.broad_jump** (change, cohort): Keep 250 cm but relabel it as sourced: 'about mean + 1 SD (~85th percentile) of young adult men (Aandstad 2021, n=21,481: 225 +/- 24 cm)'. Drop the '1.33 x height' rationale. Possibly wrong if: the athlete reaches 250 cm and it shows no link to sprint or dunk progress, or norms for trained men in their 30s turn out much higher.
- **benchmarks.pullups_max** (change, cohort): Keep 12-15 but relabel it as sourced: 'above the 75th percentile (10 reps) of young adult men on a strict dead-hang protocol (Aandstad 2021)'. Write the protocol into tests.yaml as dead hang, chin over bar, no kip. Possibly wrong if: reps at 95 kg plateau below 12 while weighted pull-up e1RM keeps rising (then a relative-load test would fit better).
- **benchmarks.run_tt_30** (change, cohort): Keep 420 s/mi as a coach stepping stone, but replace the note 'supports ~3:16 (Riegel)' with 'Riegel overestimates marathon ability (often by 10+ min, Vickers 2016); the marathon projection comes from goal_progress using long-run and mileage data'. Possibly wrong if: the athlete's own half-to-full conversion matches Riegel.
- **code.epley_e1rm** (change, cohort): Keep Epley, but when reps + RIR > 10 mark the e1RM as low-confidence: it does not set a new test result or raise working e1RM unless it is confirmed by a 10-rep-or-fewer set. Protocols stay at 3-6RM. Bump the code version in CODE_RULES. Possibly wrong if: the athlete's high-rep e1RMs agree with low-rep e1RMs within about 3% across a block.
- **code.goal_from_biggest_gap** (change, theory): Rank gaps in comparable units: gap% / goal_change_pct (blocks needed to close), ignore gaps smaller than typical_error_pct, and break ties by athlete priority or race calendar. Fallback only; Claude still proposes with a stated trade-off. Bump the CODE_RULES version. Possibly wrong if: the normalized rule picks goals the athlete rejects more often than the current rule does.
- **tests.typical_error_pct** (change, meta_analysis): hinge_rm and squat_rm 3 -> 4; row_2k 1.5 -> 2.5; run_tt_30 2 -> 2.5; keep the others (broad_jump 3, pullups 10, db_press 4) and keep flagging the rest as coaching estimates. Then refine each from the athlete's own repeat tests (Hopkins typical error from 2 or more trials). Possibly wrong if: the athlete's repeat tests show smaller within-subject variation than these values.
